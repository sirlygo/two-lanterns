# Undertoll art direction

The approved reference is `concepts/bellheart-shadow-lanterns-v2-eerie.png`.

The visual language uses crisp 2D shadow silhouettes, ragged tapering cloaks, nearly empty hooded faces, tall oppressive architecture, restrained cold fog, and small amber and mint lights. The reference guides style and character identity; each room has a distinct composition based on its story description.

## Sources

- `scenes/`: 65 regular scene illustrations and six Bell-outcome backgrounds, optimized as WebP. Alongside both room packs, Adventure adds `nim.webp`, `nim-return.webp`, `festival.webp`, `falseexit.webp`, and `huntsman.webp`. Their exact prompts use the same filenames under `prompts/` with `.txt` extensions. All five were made with the built-in image tool using the approved reference; Nim’s return also uses his first image for character continuity. See `adventure/README.md` for the image/prompt mapping.
- `portraits/`: four original calling illustrations with real alpha transparency.
- `prompts/`: exact built-in image-generator prompts, including the final dice cleanup. The title uses the approved reference; its exact prompt is in `concepts/bellheart-shadow-lanterns-v2-eerie-prompt.txt`.
- `runtime.js`: custom vector symbols and dice; generated-image scene renderer; origin and keepsake portrait details; four dynamic lantern types; two player identities; nine character fate compositions.
- `theme.css`: interface colors, framing, and slow motion matched to the approved artwork. Reduced-motion preferences disable the motion.
- `inventory.json`: the original game's complete scene, room, icon, and fate inventory.
- `manifest.json`: the final embedded asset map and scene labels, regenerated by the build.
- `qa/`: browser verification results and visual review screenshots.

The image assets were created with the built-in image generation tool, using the approved eerie reference. No API fallback or downloaded third-party art was used. The small vector symbols and adaptive lamp details are custom code assets.

## Build and review

From the project root, run:

```powershell
node scripts/build-art.cjs
node scripts/build-art-review.cjs
node scripts/verify-art.cjs
node scripts/browser-art-qa.cjs
node scripts/net-test.cjs
```

`net-test.cjs` hosts and joins a room in two browsers and needs two extra packages: `npm install --no-save peer node-turn` (see `net/README.md`).

The build replaces the art renderer, art-facing interface styling, blank-die rendering, and scene labels. It also applies `scripts/ui-edits.cjs` (play buttons and online screens), `scripts/net-edits.cjs` (connection fixes; see `net/README.md`), and `scripts/story-edits.cjs` (wandering encounters, connective passages, and banter). Each edit must match its source marker or the build stops. The ending view passes character picks to its renderer so its fate figures use the right calling and lamp. Original story data, resolution rules and saved-game keys are preserved. Fresh room draws now include one or two wandering encounters; existing saves keep their route. The full build also adds the narrator, music, sound, feats and phone support, so use `npm run build` for the playable release.

Both `index.html` and `art-review.html` embed their image data. No asset server is required to play or review them. Source images are separately retained here for future editing.
